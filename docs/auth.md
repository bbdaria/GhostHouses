# Authentication

---

## Overview

The system uses a secure authentication flow based on email, password, and a one-time verification code (OTP).  
This ensures that only authorized municipal employees can access the platform.

The authentication process includes:
- Standard login (email + password)
- 6-digit OTP verification
- JWT-based session management
- Role-based authorization across all pages

---

## Login Flow

1. The user enters their **email** and **password**.  
2. The backend checks the credentials.  
3. If valid, the server generates a **6-digit OTP code**.  
4. The user is redirected to the OTP page.  
5. The user enters the code to complete verification.  
6. A **JWT token** is issued and stored in the frontend.  
7. The user is redirected to the dashboard.

If the code is incorrect or expired, the user must request a new one.

---

## OTP (Two-Factor Authentication)

- Each OTP is valid for a short period (configurable).  
- Codes are generated by the backend and sent to the user (email or internal display during development).  
- Users cannot access any system page until OTP is verified.  
- Verification grants a short-lived session token.

---

## JWT Token

After successful OTP verification:
- The frontend receives a JWT token.  
- The token is stored securely in browser memory.  
- Every API request includes this token in the `Authorization` header.  
- The backend validates the token on each request.

If the token expires, the user must log in again.

---

## Authorization

Permissions are based on three roles:

- **Viewer**
- **Editor**
- **Admin**

The frontend protects routes using:
- `RequireAuth` (ensures user is logged in)  
- `RoleGate` (restricts pages by role)

The backend enforces permissions again for safety.

---

## Protected Routes

Examples of protected pages:

- Buildings list → Viewer / Editor / Admin  
- Building edit → Editor / Admin  
- Users list → Admin  
- Logs → Editor / Admin  

Unauthorized users are redirected back to the login page.

---

## Logout

Logging out:
- Removes the JWT token  
- Clears user data stored in context  
- Redirects to the login screen

---

## Failed Login Handling

The system handles:
- Invalid passwords  
- Expired OTP codes  
- Incorrect OTP attempts  
- Missing authentication headers  

All sensitive errors are simplified for security purposes.

---

## Conclusion

The authentication system ensures only verified, authorized municipal employees can access the platform.  
Combining login, OTP, JWT, and role-based routing provides strong protection for sensitive city data.
