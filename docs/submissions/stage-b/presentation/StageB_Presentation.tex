\begin{frame}{Architecture: Abstract vs. Concrete}
  \begin{itemize}
    \item Abstract boundaries: service contracts for JWT, OTP, audit logging, and GIS snapshots.
    \item Concrete commitments: ASP.NET Core backend, React frontend, PostgreSQL database, ArcGIS GIS provider, and Docker Compose deployment.
    \item The external-risk areas stay behind interfaces, so OTP delivery or GIS provider changes do not require rewriting controllers or the domain model.
    \item Stable runtime choices are concrete because they define how the municipality receives and operates the system.
  \end{itemize}
\end{frame}

\begin{frame}{Maintainability}
  \begin{itemize}
    \item `ApiControllerBase` centralizes authenticated API behavior.
    \item `BuildingRules` and `StreetRules` keep manual editing and Excel import aligned to one source of truth.
    \item `AppDbContext` is the persistence boundary for PostgreSQL entities.
    \item `IGisSnapshotService` protects building-card export from a future GIS vendor change.
  \end{itemize}
\end{frame}

\section{Customer-Side Deployment}
\begin{frame}{Deployment UML}
  \centering
  \includegraphics[
    width=\textwidth,
    height=0.78\textheight,
    keepaspectratio
  ]{../uml/deployment/deployment_environment.png}
\end{frame}

\begin{frame}{Customer-Side Deployment}
  \begin{itemize}
    \item The municipality environment is a Windows Server VM inside the private municipality network.
    \item The intended deployment is a Docker Compose stack: frontend, backend, PostgreSQL, and pgAdmin.
    \item Municipality users access only the frontend through HTTPS 443.
    \item IT/database administration uses pgAdmin through HTTPS 8443.
    \item Backend and database stay internal to Docker networks and are not exposed directly.
  \end{itemize}
\end{frame}

\begin{frame}{Deployment Woes and Mitigation}
  \begin{itemize}
    \item Main blocker: Docker Desktop / WSL 2 on the municipality Windows Server VM may require nested virtualization approval.
    \item We prepared the deployment as one repeatable command from \texttt{project/}: \texttt{docker compose down -v \&\& docker compose up -d --build}.
    \item We documented ports, software dependencies, hardware expectations, secrets, certificates, and network access.
    \item We prepared fallback plans with the supervisor if nested virtualization is not approved.
    \item Deployment communication is documented in writing with the client side, municipality dev team, IT/security contacts, and supervisors.
  \end{itemize}
\end{frame}
